2Product summary

BasaChai is a Bangla-first rental marketplace where owners post homes for free and tenants see the full monthly cost and call the owner directly. It pilots in Dhamrai and expands to Dhaka next.

Promiseবাসা খুঁজুন। মালিকের সাথে সরাসরি কথা বলুন। (Find a home. Talk to the owner directly.)
MarketDhamrai, Dhaka District, Bangladesh. Dhaka city after the pilot.
Pilot areasআমিন মডেল টাউন (Amin Model Town), বরাত নগর (Barat Nagor), দক্ষিণ পাড়া (Dokkhin Para), ধামরাই বাজার (Dhamrai Bazar), ইসলামপুর (Islampur). Spellings confirmed.
PlatformMobile-first responsive website; no native apps in the MVP
Business modelFree listings in the MVP; no paid placement
Who uses itTenants (search, contact), owners (post, manage), moderators and admins (review, protect)

8Listing lifecycle

A listing is visible to tenants only while Published, not hidden by a moderator, and within 30 days of its last confirmation.

  • Submit guard: required fields complete and at least 3 photos accepted by Cloudinary.
  • Approve sets last confirmed and expiry (now + 30 days). Reject and request changes require a reason the owner sees.
  • Expiry without jobs: a Live listing past its expiry is treated as Expired everywhere at read time, and the stored status is updated on the next write or dashboard visit.
  • Every transition writes availability history; moderator actions also write the moderation and audit logs.
  • Editing a Live listing (D23) keeps it Live with no new review. Each edit writes the audit log with the before and after values, so moderators can see what changed when a listing is reported.

  • Active filters show as chips, each removable; "Clear all filters" resets everything except sort.
  • The count ("১৫টি বাসা পাওয়া গেছে") is always the real number of matches.
  • Empty state: "No homes match these filters", with one-tap fixes for the filters in use: remove max rent, search all of Dhamrai, any number of bedrooms, clear all. Never show placeholder listings.
  • Area suggestions match Bangla and English spellings through curated aliases.
  • No paid ranking. Page size up to 24, with stable ordering.

10Screens

Eight screens make up the MVP; the prototype shows each one with sample data.

Home

Route /

  • Headline with the brand promise, short description, and a search form (area, max rent, bedrooms).
  • A sample cost breakdown beside the form, captioned to explain that every listing shows costs this way.
  • The 4 most recently confirmed homes: 4 across from 1,100 px, 2 x 2 from 600 px, 1 per row below.
  • "How it works" in three numbered steps, and a safety tip: see the home before you pay.

Search results

Route /search?…

  • Title names the area; live count; sort control; removable filter chips.
  • Filters in a sticky side panel on desktop; a slide-up sheet with "Show results (n)" on phones.
  • Cards: cover photo, freshness ("confirmed 3 days ago"), Save, title, area and type, key facts, total per month with split, advance.
  • Empty state as in §9.

Property page

Route /listing/{id}

  • Photo gallery with thumbnails; freshness; title; area, bedrooms, bathrooms, move-in.
  • Side panel (after the title on phones): cost breakdown; owner name with "Owner" and "Number not verified" badges; "Show number" button that becomes the number plus a Call button; "Don't send any money before you visit"; Save; Report.
  • Body: facts grid, description, amenities, owner's rules, location (area only, with a note that the owner shares the address by phone).
  • Unavailable listings show "This listing is no longer available" with a link home, and are not indexed.

Sign in

Dialog, opened from Save, Post a property or the header

  • Mobile number and password. Explains why sign-in is needed (to save, or to post).
  • Note: "We don't send codes to your phone. If you forget your password, contact support."
  • Inline errors for an invalid Bangladeshi number or a password under 8 characters. Bangla digits are accepted.

Post a property

Route /post, owners only

  1. Home details: title, type, area, bedrooms, bathrooms, size, floor, furnishing, who can rent, available from, amenities, description, rules, full address (marked private).
  2. Costs: rent, service charge, advance or "don't state", other costs with monthly or one-time.
  3. Photos: add, reorder, remove; first is the cover; "Add N more photos to submit" until 3.
  4. Review and submit: the listing as tenants will see it; "Submit for review".
  • A live cost breakdown preview stays visible beside the form on desktop.
  • Each step validates before moving on and focuses the first error.
  • Success: "Submitted for review", with links to My listings or post another.

My listings (owner dashboard)

Route /dashboard

  • Banners at the top, computed on each visit: expiring within 3 days (Still available), expired (Renew), changes needed (Edit).
  • Rows in this order: Changes needed, Draft, Expired, In review, Live, Paused, Rented, Rejected. Archived listings are not shown.
  • Draft rows offer Continue (back to the posting step where the owner left off) and Archive, so an unfinished listing is never lost.
  • The header shows a count of listings that need attention.
  • One row per listing: thumbnail, status badge, total per month, days left, views, number views, moderator's note when relevant, and actions for that status.

Moderation

Route /admin, moderators and admins

  • Counts: waiting for review, live listings, open reports, older than one business day (red when above 0).
  • Review queue, oldest first: photos, details, cost breakdown, owner, submitted time, Overdue tag; Approve, Request changes, Reject (reason required).
  • Reports: reason, tenant's note, age; Hide listing or Dismiss. Hide listing closes every open report on that listing, not just the one acted on.

Saved homes

Route /saved, signed-in users

  • Cards for saved homes that are still live; empty state invites the user to press Save on homes they like.

Navigation

Header: logo, language toggle, and links by role (Find a home, Saved, Post a property, Sign in; or My listings for owners; or Moderation for staff). Below 760 px the links become a bottom tab bar. Footer: About, How it works, Safety tips, Support, Terms, Privacy.

11Trust and safety

With no phone verification, every listing is moderated before it goes live and every contact number is labelled "not verified".

  • Moderation: every new listing is reviewed. Target: within one business day. Edits to Live listings are not re-reviewed for now (D23); the audit log and reports are the safety net.
  • Reports: anyone can report (suspicious or a scam, wrong information, posted twice, no longer available) with an optional note. Acknowledge within one business day. Hiding a listing closes every open report on it; Unhide is available on the listing.
  • Wording: never imply BasaChai has verified the advertiser or the property. "Ownership verified" is only allowed after a real ownership check exists.
  • Safety copy appears on the home page, the property page and the Safety tips page: see the home before paying anything.
  • Privacy: the full address is encrypted and never public; photo metadata, including GPS, is removed on upload; IPs and device IDs are stored hashed.

Data model

Nineteen tables: users, password_reset_tokens, locations, location_aliases, property_types, amenities, listing_amenities, property_listings (with purpose rent or sale), listing_charges, listing_photos (Cloudinary public ID), saved_listings, listing_reports, moderation_actions, listing_availability_history, audit_log, contact_events, analytics_events, app_settings, hash_salts. Money in whole taka; times in UTC; phone_verified_at kept null for later.

API

REST under api.{domain}/v1: public (listings, locations, contact, reports, events), account (auth, me, saved, attention count), owner (listings, actions, photos) and admin (stats, queue, actions, reports, users, configuration, audit). Full list in the MVP technical design and the API spec.

  • Errors are ProblemDetails with a stable code the web app maps to Bangla and English, including phone_taken (409) when a number already has an account, already_handled when another moderator acted first and rate_limited with retryAfter.
  • Search source: the browser reports each search it shows (POST /v1/events, search_performed, source home or search), because the home, area and property pages are served from the edge cache and purged by the API on change.
  • Test hooks under /v1/test/* exist only in the Test and Staging environments and are absent from production builds.
